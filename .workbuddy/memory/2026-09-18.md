## 踩到的坑（Java / Spring）

- **record 的存取方法不能改返回类型**：想把 `Boolean profileHeadless` 的取值方法写成 `profileHeadless()` 返回 boolean
  会编译失败（"存取方法返回类型必须与记录组件类型匹配"）。改名为 `useHeadlessProfile()`。
- 用 `Boolean` 而不是 `boolean` 才能区分"yml 没写"和"显式写了 false"。
- `@SpringBootTest(classes=...)` 不要把 record 型的 `@ConfigurationProperties` 写进 classes，
  Spring 会当普通 bean 装配（找不到构造器参数）→ 必须走 `@EnableConfigurationProperties`。
- Playwright 两种模式的关闭语义不同：CDP 的 `browser.close()` 只断开连接（不会关掉用户浏览器），
  `launchPersistentContext` 的 `context.close()` 才会真关进程 —— 混用会误伤。
- CDP 模式不要调 `page.setViewportSize()`：会真的改用户窗口大小（走 CDP Emulation），用户看得见。

## 登录态最终跑通（关键结论）

- 用户给的验证页：`https://wx.zsxq.com/group/51121244585524`（知识星球）。
  未登录抓到 5 字（"笔记 榜单"，登录墙）；登录态抓到 2109 字 + 真实标题"拿个offer-开源&项目实战-马丁-知识星球"。
- **CDP 这条路走不通**：Chrome 151 在**默认** user-data-dir 下会直接忽略 `--remote-debugging-port`
  （进程起来了、端口不监听）。用户自己开的 9222 就是这个情况 —— 不是占用，是根本没监听。
  要走 CDP 必须自己指定非默认 `--user-data-dir`。
- **最终用 profile 模式**：复制日常 profile 到 `~/.config/google-chrome-jlra`，yml 配 `user-data-dir`。
- ❗ 复制 profile 最大的坑：只复制 `Cookies` 会拿到近乎空的旧库（1273 条 → 1 条），
  因为 Chrome 运行时新数据在 `Cookies-wal` 里。必须 `cp Cookies*`，并带上
  `Local State`（cookie 解密密钥）+ `Local Storage` / `IndexedDB`（token 常存在这里）。
- 副本是**快照**，会过期 → 写了 `scripts/sync-chrome-profile.sh` 一键同步（已在项目里，可反复跑）。
- 全量回归：15 个测试全绿（另有 1 个手动验证用例 @Disabled）。
- 测试教训：单元测试不要断言"未登录"这种依赖 yml 配置的具体模式，否则别人配了登录态就挂。

## 收官：STORED 存档注入 + 全量回归（同日续）

- 用户提"方案一：把 sessionStorage / localStorage / cookie 抄到磁盘再注入"，实现为第 4 种模式 `STORED`：
  - `LoginStateStore`：登录成功时 `page.context().storageState()` 存 cookie+localStorage 到
    `~/.config/JLRADemo/storage-state.json`，sessionStorage 单独存到同名 + `-session.json`
    （Playwright 的 storageState **不含** sessionStorage，只能自己提取、靠 `context.addInitScript` 写回）。
  - 优先级改为 CDP → STORED → PROFILE → HEADLESS。STORED 排在 PROFILE 前：存档是"登录那一刻的快照"，
    而 profile 副本里的 cookie 会过期/被判坏。
  - 存档命令：`mvn test -Dtest='LoggedInAccessVerificationTest#saveState'
    -Djunit.jupiter.conditions.deactivate=org.junit.*DisabledCondition`
- **实测结论（修正了之前的判断）**：知识星球登录态实际在 **cookie + localStorage，不在 sessionStorage**
  （存档里 sessionStorage 是 `{}`，恢复后照样登录）。四模式字数：无头=登录页 / profile+无头=登录页 /
  profile+有头=2109 字 / **CDP=10071 字 / STORED=10071 字**。sessionStorage 代码保留（对别的站点是唯一解）。
- 全量回归：`mvn -o clean test` → **18 通过 0 失败 4 跳过**（跳过的 4 个是手动验证用例 @Disabled）。
- 规格文档 `.trellis/spec/backend/browser-automation.md` 已更新实测数据表；Trellis 任务标记 completed。

## 两个隐蔽的构建坑（浪费了不少时间）

- **Javadoc 里多写一个 `*/` 会让 Maven "编译通过"**：`LoginStateStore` 类注释提前闭合，后几行落到注释外，
  javac 报"非法字符"却被增量编译跳过，直到 Spring 加载 bean 才抛 `Unresolved compilation problems`，
  表现为**所有**测试一起挂在 ApplicationContext 上。排查口诀：满屏 `Failed to load ApplicationContext`
  且带 `Unresolved compilation problems` → 先 `mvn clean compile` 看真实编译错误，别在 Spring 配置里找。
- 枚举 switch 会生成 `Xxx$1`（switch map），上一个坑导致它没生成 → 报
  `NoClassDefFoundError: BrowserSessionProvider$1`，容易误判成依赖问题。

## 智联爬取失败根因：两个 Chrome 实例互不打通（同日续 3）

- 用户实测：`i.zhaopin.com` 已在名单，但爬到的是未登录状态。根因不是代码 bug，而是**用户登录在 2 号 Chrome，代码（LoginStateCapture / CDP）连的是 1 号 Chrome（开 9222 端口那个）**。
- 关键认知：**多个 Chrome 实例的 cookie / 登录态完全隔离**，代码只连得到"启动 `--remote-debugging-port` 那个实例"。登录和调试端口必须在同一个浏览器里。
- 之前目录里没有任何 `zhaopin` 存档，也印证了：连到的是没登录的那个浏览器 → 没存出 zhaopin 存档 → 名单命中但 `store.exists()` 为 false → 降级匿名。
- 修法加固：`LoginStateCapture` 加了守卫——当带了 `onlyHost` 过滤却一个站点都没命中时，明确报错"连到的浏览器里没有任何包含该串的页面，常见原因是登录在另一个 Chrome 了"，并列出当前浏览器实际有的站点。编译通过（mvn -o -q compile EXIT=0）。
- 正确流程（一次性）：启动专用 Chrome 带 9222 端口 → **在这个窗口里**登录智联并停在 `i.zhaopin.com/resume/new` → 跑 `mvn -o -q compile exec:java -Dexec.mainClass=com.example.domain.browser.LoginStateCapture -Dexec.args="http://127.0.0.1:9222 ~/.config/JLRADemo/state zhaopin"` → 生成 `i.zhaopin.com.json` + `-session.json` → 重新爬即登录态。

### 实测补充（同日续 3 现场）
- 用户实际起的 9222 Chrome（PID 69522，14:21 启动）只带 `--remote-debugging-port=9222`、**没有** `--user-data-dir`。
- `ss -ltnp` + `curl http://127.0.0.1:9222/json/version` 确认 **9222 根本没监听**（默认 profile 静默忽略端口），`ps` 能看到进程但连不进。
- 所以"已经登录"也白搭——代码连的都是端口，端口没开就谈不上抓取。必须让用户**退出现有 Chrome 后用显式 `--user-data-dir`（同默认目录 `$HOME/.config/google-chrome` 可保登录）重启**，端口才会真监听。
- 排查口诀：`ps` 看到带调试端口的 chrome 但 `ss`/curl 连不上 → 九成是缺 `--user-data-dir`（默认目录忽略端口），先看 `/proc/<pid>/cmdline` 有没有 user-data-dir。
