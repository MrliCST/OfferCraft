## 知识星球 API 结构（实测，2026-09-19 17:1x）—— 方案 B 的依据

- **列表**：`GET https://api.zsxq.com/v2/groups/51121244585524/topics?scope=all&count=20`
  - 单条字段：`topic_id`(数字，官方血缘键)、`topic_uid`、`type`(talk/task)、
    `talk{owner{user_id,name}, text}`、`talk.article{title, article_id, article_url, inline_article_url}`、
    `title`、`content_voice`(语音帖)、`likes_count`、`comments_count`、`reading_count`、
    `digested`(精华)、`sticky`(置顶)、`create_time`(ISO 毫秒)。
  - **翻页**：`&end_time=<本页最后一条 create_time>`（URL-encode 冒号和 +），下一页会**重复上页最后一条**，需去重。
  - 用 Playwright 的 `context.request()` 发请求即可，自动带登录态 cookie。
- **评论**：`GET https://api.zsxq.com/v2/topics/<topic_id>/comments?count=20` → `resp_data.comments[]`（实测有效）。
- **关键限制**：`talk.text` 对**星主长文只是摘要**（实测 458 字，以 `...` 结尾），
  全文仍在 `talk.article.article_url` 指向的文章页（1.4 万字）。所以 API **不能替代**文章页取全文。
- **正文是富文本 `<e>` 标记**（不是 HTML）：`<e type="text_bold" title="%E3%80%8A..."/>`、
  `<e type="hashtag" hid=... />`、`<e type="web" href="URL-encoded"/>`、`<e type="img" ...>`（图片在正文里），
  需要写解析器（或转 HTML 后复用 HtmlToMarkdown）。
- 其他接口：`/v2/groups/<gid>/topics/sticky`（置顶）、`/v2/hashtags/<hid>/topics`（按栏目）、
  `/v2/groups/<gid>/topics/tasks`（作业）、`/v2/group/<gid>/files`。

## S4 图片概括的 AiService 形态核实（2026-09-19 22:xx）

老板问「需要将他设置为一个概括图片内容的 aiservice 吗」。核实 langchain4j 1.20.0 后确认：

- **视觉输入 API**（本机源码已核实）：
  - `dev.langchain4j.data.message.ImageContent` —— 构造器/静态工厂两套：
    `new ImageContent(String base64Data, String mimeType)`、`ImageContent.from(URI url)`、
    `ImageContent.from(Path imageFilePath, String mimeType)`、`ImageContent.from(String base64, String mime)`
  - `dev.langchain4j.data.image.Image`（**包名是 `data.image` 不是 `data.message`**）：
    `Image.builder().url(...)/.base64Data(...)/.mimeType(...).build()`，取值器 `url()/base64Data()/mimeType()`
  - `UserMessage.from(TextContent, ImageContent...)` 多内容形态可用
- **AiService 参数形态（实测三个，只有一个正确）**：
  1. ❌ `String describe(ImageContent image)` —— 裸 Content 参数**没注解会报**
     `IllegalConfigurationException: The parameter 'arg1' ... must be annotated with either
     UserMessage, V, MemoryId, or UserName`（`AiServiceValidation.validateParameters` 拦截）
  2. ✅ `String describe(@UserMessage ImageContent image)` —— **可行**（框架把 Content 型
     `@UserMessage` 参数收进 contents，走到 `DefaultAiServices.addContentsToUserMessage`）
  3. ✅ `String describe(@UserMessage String prompt, ImageContent image)` 这种**不行**（第 2 个参数无注解）
     —— 要带指令就得写成方法级 `@UserMessage("请概括这张图片。")` + 单个 `@UserMessage ImageContent` 参数
- **实测结论**：两种可用形态都能正确描述图片（模拟架构图能说出「三个浅蓝矩形框横向流程图、
  框内三条黑线代表文本、相邻用黑线连接」），描述质量够用。
- **装配建议**：复用现有 `deepseekClassifyModel`（temperature=0.1，图片概括要稳定不要发散），
  `@AiService(wiringMode=EXPLICIT, chatModel="deepseekClassifyModel", streamingChatModel="deepseekStreamModel")`。
  或者为了不跟分类闸抢语义，单独加一个 `deepseekVisionModel` bean（同样 0.1，但 `maxTokens` 给足 8000）。
- **max_tokens 必须给足**：deepseek-flash 是推理模型，实测 64x64 纯色图 output 76 token
  里 74 个是 reasoning；描述一张图要给 2000+，否则 `finish_reason: length` 且 content 为空。
- **图片数据来源**：`CrawledPost.imageUrls`（Crawler 已采集，来自正文容器内 `.content img`，
  已排除水印/头像/二维码）；`zsxq_image` 表已有 `post_id/seq/original_url/kind/description/kept/embedding`。
  当前 crawl-output 的 JSON 里图片是 `![](...)` 内联在 markdown 里，imageUrls 字段未序列化进产物。
